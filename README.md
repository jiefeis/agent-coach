# Agent Coach (Agent 搭建教练)

让 Agent 搭建可控制、可解释。你能看懂每一步怎样运行、哪里出了问题，也能把这一步的修改指令交给自己的 AI。

当前版本：**v2.1.0**（以 `agent-coach` 技能调用） · [下载完整技能包 (.zip)](https://raw.githubusercontent.com/jiefeis/agent-coach/main/releases/v2.1.0/agent-coach-v2.1.0-20261125.zip) · [SHA-256 校验清单](https://raw.githubusercontent.com/jiefeis/agent-coach/main/releases/v2.1.0/SHA256SUMS.txt)

## 为什么用 Agent Coach？

手上的表有缺列，换周多了新类别，或者数字算偏了。做这类工作时，先约好拿哪两份小样核对，跑完才能看出是哪一步出了问题。

包里有排步骤、好坏小样核对和离线活地图。项目活地图看流程，外置诊断图看卡点。[业务网页指南](做法/业务网页-ELI5.md) 教你用随包模具做日报或周报。有 `sop-closed-loop-expert` 整理好的 SOP 可以直接带来，也可以从手头的 SOP 开始。

## 五站流程与双档位

| 站号 | 阶段名称 | 核心动作与产出 | 过关口令 |
| :--- | :--- | :--- | :--- |
| **第 1 站** | 建项目 | 初始化项目规矩与目录，将真实脱敏样例（支持 `.xlsx` / `.pptx` / `.docx` / `.csv` 原件）放入只读 `materials\` 目录 | `项目建好了` |
| **第 2 站** | 说清需求 / 拆 SOP | 先读样例或已有 SOP，填上已经说清的事，给一张带建议的确认单 | `任务单确认` / `拆解确认` |
| **第 3 站** | 排表画图 | 把输入放对位置，写唯一运行表 `docs\run-flow.md`（最多 7 步）。双击 `docs\run-flow.html` 看谁做、交什么、哪里等你 | `流程就这样` |
| **第 4 站** | 一步一票 | 同一对小样用两遍。开工前约好结果和错法，跑完拿两份实物对。可逐步核，也可把已经答应的纯程序步连着跑 | `票 N 通过` / `按快跑档推进` |
| **第 5 站** | 收尾交接 | 换个对话问下一步和排错文件，核对能不能接着做 | `采用` / `停止` |

**老项目换包后原地续跑**：打开项目，对 AI 说 `调用 agent-coach，体检当前项目`。双击外置诊断活地图，点开红黄步骤，看哪里断了，再把指令复制给自己的项目 AI。图里列出这一小步怎样核对。只修教练流程骨架时，可以回复 `按建议修好并接着做`。业务改动由你决定，修后打开新一轮复诊。

版本采用 `v主.次.修`：改门禁或核心交互升主版本，同时提供老项目原地续接路径；兼容的新教学或诊断能力升次版本；文案、缺陷、清单和测试修正升修订号（如 v2.0.1）。历史 v1.17 至 v1.21 按 v1.17.0 至 v1.21.0 比较。

### 这张表要怎么用

教练先看原件表头、单位和混入的小计，再按实际情况给下面一种建议。

1. **直接用**。表头、字段与单位对得上，把样例放到它该在的地方。
2. **另存一份修好**。偶尔手填、单位不明，先用少量行对照修法。保留原件，只用确认过的干净副本。
3. **每次先用程序洗一遍**。系统每次都导出多行表头或夹小计，单独排第 2 步先交一份干净表，再做计算。

### 第 4 站双档位怎么选？

* **教学档（默认）**。每跑一步，拿约好的好样本与坏样本逐一对，再看项目地图这一格到哪儿。
* **快跑档（口令 `按快跑档推进`）**。只有已经点头、无需人工核对的纯程序步能连着跑。数字对不上、坏表没拦住、遇到 AI 判断或人工停点，就停下说清楚。

### 结果怎么核、以后怎么改

* 能清点的就拿样例数一次。要算数或筛选，拿做对的旧结果、SOP 条号或小样先对。只有 AI 自己算过的，图上仍会提示等人核对。
* 先查任务单是否写齐，再等放行。仅定稿尾票的标准已定好，接班后须说 `就这样跑` 才开跑。换周先认本次文件，核当期合计能加回去，遇新类别停下问，坏表留记录。改程序时按许可用留存的旧样本重核。说“停止”就马上停。
* 改这一步只核对应单子。重排流程要一起更新主表、图和受影响的任务单。做法变了就回到第 2 站商量。

## 算错了先看哪里

双击项目活地图，点开哪一步就能看它读写的文件、约好的小样和这批跑出的结果。它是上次刷新的快照。改业务文件后请 AI 按现件刷新。 业务网页由运行表中选定的一步用当批数据生成，可以点正常、异常和待核看去向。

1. 每一步的脚本、中间文件和任务单用相同编号，一眼能找到那一组。
2. 已有的合格 Archify 图沿原入口看。文字版打开 `docs\check\run-flow.txt`。 想换项目原图时，在体检中确认先备份再升级。
3. 项目 `README.md` 会指明换表、新类别或数字对不上时先看哪一份。增删步骤时说 `同步改动`。
4. 不知道从哪查，直接对项目 AI 说 **`帮我查哪步错了`**，让它顺着输入和中间产物找第一处对不上的地方。

## 快速安装与常用口令

### 3 步安装（以 WorkBuddy 为例）

1. 下载上方的 `agent-coach-v2.1.0-20261125.zip`（保持原 ZIP，无需解压重打包）。
2. 在 WorkBuddy「技能管理 -> 添加技能 -> 上传技能」中上传该 ZIP 包。
3. 打开你自己的空项目文件夹，切换到 **Agent** 模式并勾选 `agent-coach` 技能即可开聊（在 Claude Code / Codex 中同样可直接加载本技能目录）。

### 常用口令速查

| 场景 | 你直接对 AI 说的话 |
| :--- | :--- |
| 从零开始搭新项目 | `调用 agent-coach，带我开始新项目。` |
| 跨对话恢复搭建进度 | `调用 agent-coach，接着做` |
| 诊断已有项目（外置只读不改目标） | `调用 agent-coach，体检当前项目，先不修复。` |
| 按需修复、复查并原地接续 | `按建议修好并接着做`、`只修第 1 项` 或 `修复全部硬伤` |
| 第 4 站开启纯脚本连跑 | `按快跑档推进` |
| 修改规则/增删步骤后对齐流程图与票据 | `同步改动` |
| 交付后日常排查哪里算错 | `帮我查哪步错了`（直接对项目自身 AI 说，无需调教练） |

## 运行环境与持续集成

* **运行环境**：当前面向 Windows 路径规范设计，需可用 **Node.js 22 或 24**（WorkBuddy 自带运行环境；检查器和业务网页生成器都使用 Node 自带能力）。仓库已配置 GitHub Actions Windows 双版本自动化门禁（`.github/workflows/ci.yml`）。
* **操作范围**：`materials\` 原件只读。初诊和复诊只读被检目标；修复只处理已获批的项。涉及对外发送、付款、删除 `materials\` / `work\` / `output\` 文件的操作一律交由人工执行。
* **试用提示**：静态检查器通过代表文件契约与断言核对一致，涉及模型主观生成的步骤仍请结合业务凭据审阅确认。

在 Git 仓库根目录运行 `.\工具\pack-release.ps1` 可重建安装包和校验清单，输出在 `releases\v2.1.0\`。
