# Agent Coach (Agent 搭建教练)

**带不写代码的人，按「五站法」把一件日常工作稳妥交给 AI。**

当前版本：**v1.20**（以 `agent-coach` 技能调用） · [下载完整技能包 (.zip)](https://raw.githubusercontent.com/jiefeis/agent-coach/main/releases/v1.20/agent-coach-v1.20-20261112.zip) · [SHA-256 校验清单](https://raw.githubusercontent.com/jiefeis/agent-coach/main/releases/v1.20/SHA256SUMS.txt)

## 为什么用 Agent Coach？

直接把模糊需求丢给大模型“凭感觉一次性生成”（vibecoding），最常遇到四个坑：**脏表硬读静默算错**、**口径同源盲目自证**、**次周换表出现新枚举就崩**、**过两周想改规则完全抓瞎**。

`agent-coach` 把搭建过程拆成有静态检查器（`coach-check.mjs`）兜底的**五站式工作流**：先做好原件数据治理分流，把规则边界、文件流向和真值验收标准锁死，再逐票落地。

## 五站流程与双档位

| 站号 | 阶段名称 | 核心动作与产出 | 过关口令 |
| :--- | :--- | :--- | :--- |
| **第 1 站** | 建项目 | 初始化项目规矩与目录，将真实脱敏样例（支持 `.xlsx` / `.pptx` / `.docx` / `.csv` 原件）放入只读 `materials\` 目录 | `项目建好了` |
| **第 2 站** | 说清需求 / 拆 SOP | 剥离半成品文档中的旧代码与噪音，探查原件健康度并给出**三级数据治理建议**，输出带默认推荐项的一屏确认单，按 8 类信号判定架构 | `任务单确认` / `拆解确认` |
| **第 3 站** | 排表画图 | 物理归位输入样本，锁死周期参数与已知枚举边界，生成全项目唯一步骤主表 `docs\run-flow.md`（最多 7 步，可含独立数据清洗步）与流程图 `docs\run-flow.html` | `流程就这样` |
| **第 4 站** | 一步一票 | 自动派票并预填校验值；支持**教学档**（逐票核对）与**快跑档**（纯脚本票绿灯连跑）；默认跑通交付，也可在票 01 通过后下一张票仅定稿交接 | `票 N 通过` / `按快跑档推进` |
| **第 5 站** | 收尾交接 | 生成《按症状查文件速查表》与持续运行防漂移规矩，在新会话一次核对用途、真实待办和排错位置，正式移交项目本地 AI | `采用` / `停止` |

另有独立支线：**五维项目体检与闭环复诊**（外置只读扫描任意已有 Agent 项目，输出 `P01..Pnn` 红/黄/白三色分级诊断单，支持 `修复 P01` 单点授权或 `修复全部硬伤` 批量修复、新建 `复诊-1` 验证及两轮无进展熔断，修完无损归位原停点）。

### 原件入口的三级数据治理分流（v1.20 新增）

拒绝用黑盒兼容代码硬猜脏数据，第 2、3 站与项目体检均按“自动处理是否有副作用、脏格式是否每次固定复现”明确分流：

1. **L0 干净标准件（原件直通）**：表头规整、字段类型与单位一致，直接归位进入业务步骤。
2. **L1 源头人工治理 + 清洗对照单（偶发手工脏点 / 语义歧义 / 自动强改副作用不明）**：不强写脆弱兼容代码，直接在 `docs\rules\数据清理对照单.md` 输出脏点位置与**清洗后标准数据样例（3~5 行对照）**，请学员另存修正副本并确认新文件名，保留已登记的原件，再将副本归位。
3. **L2 独立前置「数据清洗」脚本票（系统每次导出固定复现的结构性脏表）**：在运行表第 02 步单独拆出 `清洗数据` 脚本票（分别登记带本期参数的清洗摘要文件与标准底表，用边界小样核定），让下游汇总计算与脏表清洗彻底解耦。

### 第 4 站双档位怎么选？

* **教学档（默认）**：适合零基础新建项目。每跑完一张票输出一张【文件定位卡】，亲眼核对一次中间产物与坏输入拦截结果后再进下一张。
* **快跑档（口令：`按快跑档推进`）**：适合教练操盘或熟手迭代。对已确认范围内、无人工停点的 `AI照规矩` 纯脚本票，只要静态断言与坏输入测试全绿就自动连续跑通；一旦遇到断言失败、`AI看情况` 主观判断步或删改外发红线立即停下汇报。

### 验收值、持续运行防漂移与变更回退

* **分级真值核定**：清点步可用样例清点确认；**数据清洗、计算、筛选步骤**优先核旧成品、SOP 条号或 3~5 行边界小样。仅采纳 AI 同源试算时明示未做独立口径核验；取得独立对照、确认新验收单后，再更新提醒。
* **交接门禁与周期双轨**：`ticket N` 在写程序前检查票面，`accept N` 核已获运行许可的产物。仅定稿尾票未经批准不会在接班后自动运行（接班后须说 `就这样跑` 才执行）。换周复跑核当期参数、总额/行数守恒、**已知枚举白名单（遇新增未知状态停机报人）**及坏输入拦截；改脚本、计算规则或同步改动后，按票面许可重跑绑定基线样例。使用者说“停止”立即停下并登记未完项。
* **三级改动回退路由**：只调单步公式/文风 → 原地改单票重跑基线；增删步骤、改角色停点或改跨步文件流向 → 回更 `docs\run-flow.md`、重画 `Archify` 流程图并重拆对齐 `docs\tickets\`；任务变为动态探索或多 Agent 异步协同 → 回查架构推荐表拆分。

## 四重文件定位锁（防黑盒设计）

为了避免跑通交付后“不知道哪步出错、不知道去哪改文件”，生成出的每个项目都自带四层定位机制：

1. **物理一步一档**：严格保持 `scripts\NN_短名.js`、`work\NN-中间结果`、`docs\tickets\NN-短名.md` 编号一一对应，绝不混成单文件大黑盒。
2. **每步文件定位卡**：每次跑票固定展示“读了谁 → 写了谁 → 真值抽样 → 以后这类问题改哪个文件”。
3. **README 症状速查表**：在生成项目的 `README.md` 内固化“换表报错看哪、出现新枚举查哪、数字算错查哪个 `work\` 文件、增删步骤怎么同步图和票”的对号入座表。
4. **内置自诊口令**：日常使用遇到报错或结果不符，直接对项目 AI 说 **`帮我查哪步错了`**，AI 会顺着 `inputs\ -> work\01..N -> output\` 逐级核对并报出第一处出错的步骤与文件。

## 快速安装与常用口令

### 3 步安装（以 WorkBuddy 为例）

1. 下载上方的 `agent-coach-v1.20-20261112.zip`（保持原 ZIP，无需解压重打包）。
2. 在 WorkBuddy「技能管理 -> 添加技能 -> 上传技能」中上传该 ZIP 包。
3. 打开你自己的空项目文件夹，切换到 **Agent** 模式并勾选 `agent-coach` 技能即可开聊（在 Claude Code / Codex 中同样可直接加载本技能目录）。

### 常用口令速查

| 场景 | 你直接对 AI 说的话 |
| :--- | :--- |
| 从零开始搭新项目 | `调用 agent-coach，带我开始新项目。` |
| 跨对话恢复搭建进度 | `调用 agent-coach，接着做` |
| 诊断已有项目（外置只读不改目标） | `调用 agent-coach，体检当前项目，先不修复。` |
| 按体检分级单勾选或批量修复并复诊 | `修复 P01、P02` 或 `修复全部硬伤` |
| 第 4 站开启纯脚本连跑 | `按快跑档推进` |
| 修改规则/增删步骤后对齐流程图与票据 | `同步改动` |
| 交付后日常排查哪里算错 | `帮我查哪步错了`（直接对项目自身 AI 说，无需调教练） |

## 运行环境与持续集成

* **运行环境**：当前面向 Windows 路径规范设计，需可用 **Node.js 22 或 24**（WorkBuddy 自带运行环境；`工具\coach-check.mjs` 为零外部依赖原生脚本）。仓库已配置 GitHub Actions Windows 双版本自动化门禁（`.github/workflows/ci.yml`）。
* **操作范围**：`materials\` 原件只读。初诊和复诊只读被检目标；修复只处理已获批的项。涉及对外发送、付款、删除 `materials\` / `work\` / `output\` 文件的操作一律交由人工执行。
* **试用提示**：静态检查器通过代表文件契约与断言核对一致，涉及模型主观生成的步骤仍请结合业务凭据审阅确认。

在 Git 仓库根目录运行 `.\工具\pack-release.ps1` 可重建安装包和校验清单，输出在 `releases\v1.20\`。
