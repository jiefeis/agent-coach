**当前分支是待验证候选：以 v1.16 r9a（2026-10-26）技能源码为基线。本地 handler 合成断言已通过；WorkBuddy 宿主能力尚未验证，两项实机问题仍未闭合。**

本轮按“先同步至 GitHub，再进行测试”的顺序推进。源码与隔离实验先提交供审阅，远端内容核对后再运行检查和实机验证；暂不提供新的安装 ZIP。下面的下载入口仍是历史 v1.12 / v1.11，不包含本轮实验。

## 这是什么

`agent-coach` 是一个带你在自己的项目里完成工作的 AI 技能。五站依次是建项目、说清需求、排表画图、一步一票、收尾交接；也支持已有项目的体检、按问题编号确认修复、复诊后接回原任务，以及已确认改动的“同步改动”。

本分支沿用 v1.16 r9a 的验收单语法预检、项目进度与交接接续规则。既有版本的检查结论只适用于各自已验证的内容，不能当作本轮 Hook 代码通过的证据。

## 隔离实验与验证边界

`experiments/workbuddy-hook-probe/` 用于非活动的能力探针、配置示例和最小合成检查，普通技能入口不会启用它。实验只面向一个新建的合成项目和本场固定输入，不读取真实项目、其他聊天或用户级记忆，不注册全局 Hook。

当前调查目标为 WorkBuddy 5.9.2。CLI 文档或代码中的项目配置标识不代表桌面宿主已经支持。同步后的验证需分别确认局部配置是否加载、原始输入是否可信、宿主是否在目标修改前遵守阻断，以及实验能否停用；没有收到事件或不能确认隔离时应停止。处理函数返回拒绝，也不等于宿主已经阻止写入。

初始代码提交 [`6684194da5fd23e32b0fad38c20013275eeb7d45`](https://github.com/jiefeis/agent-coach/commit/6684194da5fd23e32b0fad38c20013275eeb7d45) 上传时，本轮新测试尚未运行。远端核收后，已从该提交下载 ZIP 并新解压，在 Node.js 24.14.1 运行 `guard.test.cjs`：handler 合成断言通过，退出码为 0。该检查未操作 WorkBuddy 宿主。

WorkBuddy 5.9.2 的宿主验证仍待正常打开本次新合成项目，尚未投递模型消息。Hook 加载、宿主原话获取及实际阻断均未验证，当前不判为平台失败；Q-ORDER-01 与 Q-QUOTE-01 仍开放。

后续结果继续绑定实际提交，区分逻辑检查、宿主能力及真实动作顺序；项目级探针不代表完整五站、其他工具或其他平台已经通过。未经验证的候选不替换已安装技能，也不升级为正式 Release。

## 安装与使用历史技能包

当前面向 Windows，需可用 Node.js 22 或 24（WorkBuddy 自带运行环境）。在 WorkBuddy 的技能管理中上传原 ZIP；如平台要求手动安装，按包内 README 放置技能文件。

打开自己的项目文件夹，使用可操作项目文件的“办公”模式，在已安装技能中选 `agent-coach` 并点“去试试”。不同版本的模式名称可能不同，实际加载以当前任务读取的技能入口为准。先输入：

> 调用 agent-coach，体检当前项目，先不修复。

看完报告后，再按问题编号确认需要修复的范围。权限弹窗出现时，先核对项目和报告路径，再按需授权。新项目可说“调用 agent-coach，带我开始新项目。”；已有批准的改动需要对齐文件时，可说“同步改动”。

项目文件放在自己的工作目录，技能文件夹只放技能。升级前完整备份旧技能，再替换新包的同名成员，保留用户附加文件；不要清空目录或安装两个同名副本。平台记忆可以保留，项目进度以 `docs/PROJECT_INDEX.md` 为准，无需删除 `.workbuddy`。
