## 这是什么

`agent-coach` 是一个带你在自己的项目里完成工作的 AI 技能。五站依次是建项目、说清需求、排表画图、一步一票、收尾交接；也支持已有项目的体检、按问题编号确认修复、复诊后接回原任务，以及已确认改动的“同步改动”。

本分支以 v1.16 r9a 为基线，保留验收单语法预检、项目进度和交接接续规则。产品包仍为完整包 24 成员、首站包 11 成员；包内 README 沿用 r9a 的安装说明，本页是独立的公开候选说明。测试、实验及开发补丁不进入技能包。

## r10 的窄 repair 入口

`coach-check` 的 `repair` 由 AI 在已有适用授权下调用，只接受最新版 `AI 自检` 区唯一一行的等价修正：将包含关系中的一个“有”改成“含”，路径、期望文本、空白、标点和引号均保持。其它修法、旧版内容或业务标准变更不属于此入口；不新增业务确认或验收版，也不执行票和业务脚本。

六字段输入绑定当前票的原字节摘要、最新验收版、项目内来源文件及其摘要，以及两条完整的旧行/新行。程序直接读取来源原文，不接受另一份模型填写的引语或“已授权”标记。它先排他创建独立 JSON 来源回执并读回核同，再将一字修正与结果段记录一次原子提交到票文件，保留原 BOM、原有 LF/CRLF（含混合）换行和其余字节。票内原文以围栏中的 JSON 字符串保存，避免多行内容被解析成新的标题或活动链接。

**来源文件核同只证明该文件的身份和字符，不证明宿主消息真实，也不授予修复权限。** 仍须核对本次票版和范围适用的真实授权；不能把模型复述存成文件后称为原始消息。前置来源回执描述的是提交前时点，最终阶段须结合退出码、实际票和最终报告判断。

| 退出码 | 阶段含义 |
| --- | --- |
| 0 | 已提交，最终核验和报告成功。 |
| 1 | 提交前拒绝或失败，目标票原字节未动；可能已产生前置回执或临时文件。 |
| 2 | 已提交，但后续回执或核验未完成；停止并查看实际目标及本次证据，不能当作未修改后自动重跑。 |

这是串行单票的限定入口，不是通用审批系统或任意文本补丁器，不承诺跨进程并发安全。新增 `repair`、定向检查及相应 L0 门目前尚未运行，以上行为仍待对应提交的局部验收。

## 安装与使用历史技能包

当前面向 Windows，需可用 Node.js 22 或 24（WorkBuddy 自带运行环境）。在 WorkBuddy 的技能管理中上传原 ZIP；如平台要求手动安装，按包内 README 放置技能文件。

打开自己的项目文件夹，使用可操作项目文件的“办公”模式，在已安装技能中选 `agent-coach` 并点“去试试”。不同版本的模式名称可能不同，实际加载以当前任务读取的技能入口为准。先输入：

> 调用 agent-coach，体检当前项目，先不修复。

看完报告后，再按问题编号确认需要修复的范围。权限弹窗出现时，先核对项目和报告路径，再按需授权。新项目可说“调用 agent-coach，带我开始新项目。”；已有批准的改动需要对齐文件时，可说“同步改动”。

项目文件放在自己的工作目录，技能文件夹只放技能。升级前完整备份旧技能，再替换新包的同名成员，保留用户附加文件；不要清空目录或安装两个同名副本。平台记忆可以保留，项目进度以 `docs/PROJECT_INDEX.md` 为准，无需删除 `.workbuddy`。
