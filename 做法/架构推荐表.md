# 架构推荐表

从上往下查，命中第一行就停。

| 信号 | 学员常这样说 | 架构（白话名＋六类叫法） | 第一版 | 停不停 |
|---|---|---|---|---|
| 一次性 | 就这一次 | 不搭（一次性） | 第 2 站当场做完，结果写进 output\ | 结束 |
| 现成工具 | 学员自己说手上的工具或说明能做完 | 不搭（现成工具） | 给用法，写进 README | 结束 |
| 几块 | 这件事分几块，三样同时不同：输入不同、交出的东西不同、核的人不同（只是输出文件多不算；每块都有别的块不用的输入，接前一块核过的产出不算输入相同） | 几个 Agent 接力（Multi-Agent） | 这一版不搭。起步建议：先挑一块，另说"带我开始新项目"只讲那一块，照固定流程搭 | 给完推荐就停 |
| 分类 | 先看每份（每封、每条）是哪一类，再按那一类的办法办 | 固定流程·先分类再办（Workflow／编排组织类，单 Agent） | 照五站搭：用一步"AI看情况"判成哪一类，拿不准的归"其他"；第一版只分类，只办第一问那一类 | 进第 3 站 |
| 固定 | 说得出每次的几步，每次一样，每步做的事也一样（只是换了数据不算不一样）；某步要看内容判断也算。每次要做的事本身不同、开工前看了要求才列得出的，不算固定，看"清单" | 固定流程（Workflow／编排组织类，单 Agent） | 照五站搭 | 进第 3 站 |
| 查找 | 查一处看结果再定下一处；有时一处就查到，有时要查好几处 | 边查边定（ReAct，单 Agent） | 这一版不搭。起步建议：只读几份表，最多查 5 次，每次记一行，查不到就停 | 给完推荐就停 |
| 清单 | 每次要做的事不同（这次要准备的几样和上次不一样），排不出一张每次通用的运行表；但开工前看过要求就说得出这次要做哪几件 | 先列计划再做（Plan-and-Execute，单 Agent） | 这一版不搭。起步建议：先只列计划、由你核，不照计划做 | 给完推荐就停 |
| 说不出 | 问过举例问，还是说不出上次是怎么做的 | 不搭（先人工做几次） | 先人工做 3 次，把经过记下来再来 | 结束 |

- 六类叫法：单 Agent、Workflow、编排组织类（并进 Workflow）、ReAct、Multi-Agent、Plan-and-Execute。推荐一行两样都写：白话名，括号里是叫法。
- 两个信号都像，按表的先后取，但学员的话落在某行写明"不算"的情形里，先跳过那一行。信号从学员本站说过的所有话里认（第一问的回答也算），有一行命中就用它；举例问答"不能""说不出"不改已命中的信号，学员改口说前面说错了，照改口的重认。一行都没命中才换一次经历再问一次举例问（算一问），仍没命中走"说不出"。不默认"固定"，不把"说不出"直接判成先列计划再做。
- 加项只有"＋做完按清单查"一个，只准跟在"分类""固定"后面。条件是"错的样子"能照一张写得清的清单查出来；满足就在架构名后加这个后缀，运行表在交你之前加一步"AI照规矩：按清单查"。"AI 只做只读和草稿""最多改 2 次"这类本项目的限制不算加项，接在"第一版"那一行后面写。

## 推荐句

> 推荐你用「<架构>」，因为你说"<原话>"。第一版：<第一版>。不对就直接说，我按你说的改。

学员要改成更复杂的，先说一句"更费积分、更难验"，他坚持就照改。改后的架构必须是表里的名字，停不停按改后的架构判。

## ⑥ 的写法

学员改了推荐，另加一行 `你改成：<架构>｜日期｜原话`。files 从第 2 站起每站核⑥。
