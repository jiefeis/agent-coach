# 做法 2（SOP）：拆开 SOP

## 0 路径和检查
- 检查写法：`node "<教练文件夹>\工具\coach-check.mjs" <命令> "<学员项目完整路径>" <站号>`。路径照原样，末尾不加 `\`；找不到 node 就用平台自带 node 的完整路径。

## 1 开场、“半成品 SOP 去噪”与原件数据治理探查
学员说"开始第 2 站"或"接着做"后，读学员项目的 `docs\PROJECT_INDEX.md`，确认"当前站"是"2 说清需求"、路线是"SOP"。路线是新做，改读 `做法\2-新做-说清需求.md`；当前站不对，照规矩第 4 条。在 `materials\` 里找到 SOP 原件完整读完，同时探查其余样例文件（`.xlsx` 看表名、表头行位置、合并单元格与尾行小计；`.pptx` 看页数、占位框与原生图表；`.csv` 看编码、分隔符与前几行）。认不出哪份是 SOP，请学员打字说。

**半成品 SOP 去噪**：若 SOP 原件里混杂了“指挥 AI 的提示词、Python/JS 代码块、培训背景故事、多角色异步协同分支”，**不要照单全收**：
- 自动把代码/背景剥离（若有现成脚本，仅在 `INTAKE.md` 备注为参考附件）；
- 优先抽出**单操作人、单次闭环的纯业务步骤与硬口径**（保留原表名、列名、计算公式、阈值、页码映射，每条硬公式、过滤条件、停跑阈值末尾附原件出处，例如［原 SOP §4.1］；低频安全兜底也逐条保留。没有条号则记页码、段落或表格位置）；
- 若存在跨角色异步分支（如批处理、事后协同改稿），按 `做法\架构推荐表.md` 建议先做单次闭环第一版。

**原件数据治理三级分流（拒绝黑盒硬猜脏数据）**：根据样例探查结果，判断“自动处理是否有副作用、脏格式是否每次固定复现”，归入以下三类之一：
- **L0 干净标准件（原件直通）**：首行表头清晰、单位与类型一致、无合并错位，第 3 站直接归位读取。
- **L1 源头人工治理 + 清洗对照单（偶发手工脏点 / 口径混填歧义 / 自动强改会产生副作用或说不准实质收益）**：**绝不写脆弱兼容代码硬猜**。向学员明确指出原件哪里脏，并在 `docs\rules\数据清理对照单.md` 写出《原件清理项与清洗后标准数据样例（3~5 行干净表头与标准值对照）》。在 `docs\PROJECT_INDEX.md` 文件地图逐件登记用途及适用步骤，并在学员项目 `AGENTS.md` 写明处理该输入时先读 `docs\rules\数据清理对照单.md`。请学员将源头清理后的副本以新文件名加入 `materials\`，保留基线原件。
- **L2 前置独立数据清洗脚本（系统每次导出固定复现的结构性脏数据，如固定多行标题横幅、千分位文本数字、固定夹杂小计行）**：约定在第 3 站 `run-flow.md` 第 02 步单独拆出 `AI照规矩` 的「清洗数据」步骤（把脏数据转为标准干净表），与下游业务计算彻底解耦。

第一条消息开头照抄："第 2 站我们把 SOP 洗成清晰的业务边界、数据治理方案与缺项清单。"

## 2 写精简版 INTAKE.md
照 `<教练文件夹>\模板\docs\INTAKE-SOP.模板.md` 写学员项目的 `docs\INTAKE.md`：
- 不再抄写冗长的全量步骤表（步骤明细统一留到第 3 站 `run-flow.md` 单表维护），只写清：**① 单次闭环目标、唯一操作人与数据治理分流结论**、**② 关键业务硬口径与角色边界摘要**（标注哪些是 `照规矩做`、哪些是 `要看情况`、哪些是 `要你拿主意`）、**③ 缺项清单**、**④ 架构推荐**。

## 3 一屏集中确认（替代 5 轮盲问）
先通过探查 `materials\` 里的样例，自行尽可能把能看出的信息填上，然后把**真正拿不准的缺项、数据治理选型与边界问题（最多 5 项）**汇总成**一屏带默认推荐项的《边界与缺项确认单》**：
1. 必须包含对流程走向与**数据治理方式（L0 直通 / L1 源头修原件附清洗样例 / L2 拆独立清洗脚本步）**的确认（SOP 每次是否固定按这几步做；做错了能否打开输出文件核出对错）。
2. 每个缺项下面直接给出**AI 根据样例推断的推荐默认项**（标明“建议：……”），同时允许学员直接回复“全按建议”或逐条修改（如 `1改xxx，其余按建议`）。
3. ⑥ 照 `做法\架构推荐表.md` 查表预填四行，随确认单一起展示。

交结果单后停下。要你拿主意写："请核对以上边界、数据治理建议与推荐默认值，有要改的直接说序号；没问题请回「拆解确认」"，下一步写：`你说"拆解确认"，我就核对文件并进入第 3 站（⑥是不搭（一次性）的写：我就照 SOP 做完，结果写进 output\）。`

## 4 学员说"拆解确认"
把学员确认或修改后的内容写回 `docs\INTAKE.md`（未改的采纳建议值并标"已确认"；若定为 L1 源头治理且尚未生成对照单，同步写好 `docs\rules\数据清理对照单.md` 并提醒学员在进第 3 站前确认新增干净副本的文件名），第 2 行的"还没说"改成今天日期。
⑥的架构是下面这些的，办完本站就结束（照 `做法\架构推荐表.md` 判）：
- 不搭（一次性）：现在照 SOP 做完，结果只写进 `output\`；记"已结束（一次性做完）"。
- 不搭（现成工具）：结果单写清用法，也写进 `README.md`"怎么开始"。记"已结束（已给出用法）"。
- 不搭（先人工做几次）：结果单写清先人工做 3 次，把经过记下来再来。记"已结束（先人工做几次）"。
- 边查边定、先列计划再做、几个 Agent 接力：结果单写推荐和第一版。记"已结束（推荐：<架构>）"。
有"你改成"的，按改后的架构判。

用检查跑 `files`，站号写 `2`。不通过：把点名的告诉学员，照规矩第 8 条处理后再跑。
通过：照规矩第 8 条在"每站完成记录"加一行。本站结束的，"当前站"改成记作的那句；未结束的（搭建流程表），"当前站"改成"3 排表画图"，"下一句话说"写"开始第 3 站"，`README.md`"它做什么"写"拆解完成，待排流程表"。报完整路径和结果单上的话，停下等学员。
