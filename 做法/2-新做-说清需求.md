# 做法 2（新做）：说清需求

## 0 路径和检查
- 检查写法：node "<教练文件夹>\工具\coach-check.mjs" <命令> "<学员项目完整路径>" <站号>。路径照原样，末尾不加\；找不到 node 就用平台自带 node 的完整路径。

## 1 开场
学员说"开始第 2 站"或"接着做"后，读学员项目的 docs\PROJECT_INDEX.md，确认"当前站"是"2 说清需求"、路线是"新做"。路线是 SOP，改读 做法\2-SOP-拆开SOP.md；当前站不对，照规矩第 4 条。
再看 materials\ 每份文件的开头几行。
进度记录有"接自"：先读体检报告，预填任务单，只问缺的，⑥用报告里的推荐。进度记录有"旧记录："那一行，或学员本站说旧网页做过一半又不体检的：⑥"架构"只抄表名，"因为"先写一句旧记录的说法（如"旧记录选了 Agent 路线"），再写你的依据。
第一条消息开头照抄："第 2 站我们写一页任务单。我一次问一个问题，最多 5 个。"

## 2 问问题
按顺序一次问一个，问满 5 个就停：
- 第一问："如果只能先做一小块、用一个真样例验证，先做哪块？"
- A（进度记录"已确认"或材料看得出就跳过）："这件事是不是每周或每次都要重复做？"
- 举例问："拿最近一次举例：你第一眼看什么，接着做了什么，最后交出什么？每次都这样吗？"学员的原话记进任务单①"每次的步骤"。
- 推荐句：学员一答完举例问，下一条消息开头照 做法\架构推荐表.md 的"推荐句"说（不算一问）。两个信号都像按表的先后取；信号怎么认、几时再问举例问，照 做法\架构推荐表.md 表下第 2 条。
- 对的值："拿 materials 里一份样例，这一块应该得到什么？请说 1 到 3 个你确定的值。"
- 错的样子："什么样的结果你一看就知道错了？"答的是一张写得清的清单（信号是"分类""固定"），⑥架构后加"＋做完按清单查"，下一条消息告诉学员。
- C（看得出就跳过）："做错了，能不能靠打开文件看判出来？"没问到时，"错的样子"答得出就算能（由前面的回答推断）；推不出写"不能"。
每问写在消息里，末尾加"请直接打字回答。"，不用选择题弹窗，不列候选。答不上的写"待确认"。

## 3 写任务单
照 <教练文件夹>\模板\docs\INTAKE-新做.模板.md 写学员项目的 docs\INTAKE.md。没问到、材料里也看不出的栏，写"待确认"，列进⑨。
⑥ 照 做法\架构推荐表.md 查表，写四行。

交结果单后停下。要你拿主意写"请逐栏看任务单，哪栏要改？"（④列出冲突的，改问这条冲突），下一步写：你说"任务单确认"，我就核对文件（⑥是不搭（一次性）的写：我就照任务单做完，结果写进 output\）。

## 4 学员说"任务单确认"
任务单第 2 行的"还没说"改成今天日期。
⑥的架构是下面这些的，办完本站就结束（照 做法\架构推荐表.md 判）：
- 不搭（一次性）：现在做完，结果只写进 output\ 的新文件，对照④逐例核；结果单要你拿主意写"请打开 output\ 对照④看，哪份不对？"。记作"已结束（直接做完），结果在 output\"。
- 不搭（现成工具）：结果单写清用法，也写进 README.md"怎么开始"。记作"已结束（已给用法）"。
- 不搭（先人工做几次）：结果单写清先人工做 3 次，把经过记下来再来。记作"已结束（先人工做几次）"。
- 边查边定、先列计划再做、几个 Agent 接力：结果单写推荐和第一版。记作"已结束（推荐：<架构>）"。
有"你改成"的，按改后的架构判。
用检查跑 files，站号写 2。不通过：把点名的告诉学员，照规矩第 8 条处理后再跑。
通过：照规矩第 8 条在"每站完成记录"加一行。本站结束的，"当前站"改成记作的那句，下一句该说和换对话时说都写"无"，README.md"它做什么""结果在哪"各写一句，交结果单。其余的，"当前站"改成"3 排表画图"，下一句该说写"开始第 3 站"，交结果单，照规矩第 8 条加最后一行。
