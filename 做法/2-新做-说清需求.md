# 做法 2（新做）：说清需求

## 0 路径和检查
- 检查写法：`node "<教练文件夹>\工具\coach-check.mjs" <命令> "<学员项目完整路径>" <站号>`。路径照原样，末尾不加 `\`；找不到 node 就用平台自带 node 的完整路径。

## 1 开场
学员说"开始第 2 站"或"接着做"后，读学员项目的 `docs\PROJECT_INDEX.md`，确认"当前站"是"2 说清需求"、路线是"新做"。路线是 SOP，改读 `做法\2-SOP-拆开SOP.md`；当前站不对，照规矩第 4 条。
先探查 `materials\` 每份文件的结构与开头内容。进度记录有"接自"：先读体检报告，预填任务单，只问缺的，⑥用报告里的推荐。第一条消息开头照抄："第 2 站我们把需求边界和样例预期值一次对齐。"

## 2 一屏集中确认（替代 5 轮盲问）
先根据 `materials\` 里的真实样例起草 `docs\INTAKE.md`（照 `<教练文件夹>\模板\docs\INTAKE-新做.模板.md`），然后把需要学员拍板的事项整理成**一屏带默认推荐项的《需求与样例确认单》**（最多 5 项）：
1. **第一版先做哪一小块**：给出基于样例的切块建议；
2. **重复性与做法**：是否每周/每次重复做，以及常规步骤顺序（给建议值）；
3. **对的值（1~3 个预期校验值）**：AI 先读一份真实样例试算出参考值供学员核对，请学员确认或给出自己手算/旧成品里的真值；
4. **错的样子**：给出 1~2 个常见错法候选（若能用清单查出，⑥架构后加 `+做完按清单查`）；
5. **风险与边界**：对外发消息、改别人表、不可撤回动作是否需要人卡住（默认标为必须人确认）。

⑥ 照 `做法\架构推荐表.md` 查表预填四行，随确认单一起展示。
交结果单后停下。要你拿主意写："请核对任务单与推荐默认值，有要改的直接说序号；没问题请回「任务单确认」"，下一步写：`你说"任务单确认"，我就核对文件并进入第 3 站（⑥是不搭（一次性）的写：我就照任务单做完，结果写进 output\）。`

## 3 学员说"任务单确认"
把学员确认或修改后的内容写回 `docs\INTAKE.md`，任务单第 2 行的"还没说"改成今天日期。
⑥的架构是下面这些的，办完本站就结束（照 `做法\架构推荐表.md` 判）：
- 不搭（一次性）：现在做完，结果只写进 `output\` 的新文件，对照④逐例核；记作"已结束（一次性做完）"。
- 不搭（现成工具）：结果单写清用法，也写进 `README.md`"怎么开始"。记作"已结束（已给出用法）"。
- 不搭（先人工做几次）：结果单写清先人工做 3 次，把经过记下来再来。记作"已结束（先人工做几次）"。
- 边查边定、先列计划再做、几个 Agent 接力：结果单写推荐和第一版。记作"已结束（推荐：<架构>）"。
有"你改成"的，按改后的架构判。

用检查跑 `files`，站号写 `2`。不通过：把点名的告诉学员，照规矩第 8 条处理后再跑。
通过：照规矩第 8 条在"每站完成记录"加一行。本站结束的，"当前站"改成记作的那句；未结束的（搭建流程表），"当前站"改成"3 排表画图"，"下一句话说"写"开始第 3 站"，`README.md`"它做什么"写"需求已说清，待排流程表"。报完整路径和结果单上的话，停下等学员。
