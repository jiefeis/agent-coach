# 做法 5：收尾交接

## 0 路径和检查
- 旧布局照 `做法\共用.md` 第 1 节。
- 检查写法：`node "<教练文件夹>\工具\coach-check.mjs" <命令> "<学员项目完整路径>" <站号>`。路径照原样，末尾不加 `\`；找不到 node 就用平台自带 node 的完整路径。

## 1 开场
"同步改动"先照 `共用.md` 第 5 节，返回本节原停点，不要求再说开始、不跑票或升站；其余请求再照下面开场。
学员说"开始第 5 站"或"接着做"后，读进度记录，确认"当前站"是"5 收尾交接"；不对照规矩第 4 条。
第一条消息开头照抄："第 5 站收尾：生成排错地图并把项目交给你自己的 AI。"
读学员项目的 `AGENTS.md`、`README.md`、`docs\PROJECT_INDEX.md`、`docs\INTAKE.md`、`docs\run-flow.md` 和 `docs\tickets\`。

## 2 核 AGENTS.md 与内置“自诊口令”
- 确认 `AGENTS.md` 没有"待填"，"步骤"一节和运行表对得上。
- `AGENTS.md`、`README.md` 都不提教练：没有"教练"、教练文件夹的路径、"做法"。
- 检查 `AGENTS.md` 是否已包含 **`帮我查哪步错了`** 自诊规矩（确保项目自己的 AI 日常遇到报错或结果不对时，会顺着 `inputs\ → work\01 → work\02 → ... → output\` 逐级比对，直接定位到故障步骤、脚本和文件）。
- 还没定的事：把 `INTAKE.md` 缺项、运行表里的"建议值，待确认"和进度记录的"待确认"一次性念给学员，问要不要现在定；只锁定学员明确确认的值，其余保留待确认，并标明影响哪一步。

## 3 填全 README（升级为“按症状查文件”排错地图）
照运行表和票写，换掉每个"待填"，每节一到三句：
- 它做什么 / 怎么开始 / 输入放哪 / 结果在哪 / 哪步要人判断 / 怎么判断对错（保留`"通过"只表示这份样例在这一步对了`）。
- **重点填全《按症状查文件（排错速查表）》**：根据本项目实际步骤，写 3~5 行大白话排错表（例如：认不出新表看哪、中间数字算错先打开 `work/` 哪个文件、文案口气不对改哪张票或 `AGENTS.md` 哪一条），以及提醒“日常遇到问题直接对项目 AI 说 **`帮我查哪步错了`**”。

若有同源试算，README“它做什么”下列出步号、来源和首次正式投产前的旧成品复核提醒。把真实下一张票及三态（或第 NN 步人工核对）写入进度。尾票仅定稿时不宣称全链路已跑通。

## 4 一次新会话接班与排错演练
请学员在项目里另开新对话，不调用教练，只问：
“这个文件夹里的 Agent 是做什么的？下一步该做哪张票或哪项人工判断（依据哪份文件）？如果中间某步算出的数字不对，我该先打开哪个文件排查？”
核四项：用途与 README 一致；下一步、票面状态和依据与实际进度一致，没有偷跑脚本或把未完事项说成完成；指对 work 里的中间文件或给出“帮我查哪步错了”口令；回答全程不提教练。四项全中才请学员采用；否则只修本次差异，再核接班结果。

## 5 再改一轮
学员说"再改一轮"：问"改哪处？"，留在第 5 站改，"当前站"不后退，已有的票不重出：
- 改说明文字或排错表：只复核受影响的接班回答，符合第 4 节四项标准才等“采用”。
- 改流程：只改每步的做法、从哪拿、放到哪和判断；要增删步或挪"你"那步，得回到第 3 站重排（"当前站"改回 3）。
- 改某张票：追加新一版验收单，已获新版运行许可才实跑并验收；仅定稿票只跑 ticket，按实际状态交结果单。

## 6 过关
- 采用：在“## 已确认”记决定、范围及学员原话并读回。流程改过先跑 accept 01，其他受影响且已授权的票按本版重验；仅定稿的尾票只跑 ticket。再跑 files 5，读报告通过后标为“已结束（采用）”，保留下一步和真实票面状态，换对话时说“接着做”。
- 停止：立即停手，不跑 files 5 或 accept，不改 output。在进度记录写“日期 ｜ 停止 ｜ 已完成项与未完项 ｜ 学员原话”，标为“已结束（停止）”并读回。写盘失败报未记妥，保持停止，不记作验收通过。
