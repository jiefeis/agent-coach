# 做法 5：收尾交接

## 0 路径和检查
- 旧布局照 `做法\共用.md` 第 1 节。
- 检查写法：`node "<教练文件夹>\工具\coach-check.mjs" <命令> "<学员项目完整路径>" <站号>`。路径照原样，末尾不加 `\`；找不到 node 用平台自带 node 的完整路径。

## 1 开场
"同步改动"先照 `共用.md` 第 5 节，返回本节原停点，不要求再说开始、不跑票或升站；其余请求再照下面开场。学员说"开始第 5 站"或"接着做"后，读进度记录，确认"当前站"是"5 收尾交接"；不对照规矩第 4 条。
首行路标后说："这站看看换个对话能不能接着做，算错时能不能找到第一份该看的文件。"读学员项目的 `AGENTS.md`、`README.md`、`docs\PROJECT_INDEX.md`、`docs\INTAKE.md`、`docs\run-flow.md` 和 `docs\tickets\`。

## 2 核 AGENTS.md、内置“自诊口令”与持续运行护栏
- 确认 `AGENTS.md` 没有"待填"，"步骤"一节写明`共 N 步`且和运行表对得上。
- `AGENTS.md`、`README.md` 都不提教练：没有"教练"、教练文件夹的路径、"做法"。
- 核项目有“帮我查哪步错了”的说法、换新表前先清掉旧批输入的规矩、新类别要停下来问，以及改这一步、重排流程、重新选做法各从哪儿开始。
- 还没定的事：把 `INTAKE.md` 缺项、运行表里的"建议值，待确认"和进度记录的"待确认"一次性念给学员，问要不要现在定；只锁定学员明确确认的值，其余保留待确认，并标明影响哪一步。

## 3 给接班的人写一张找文件的说明
照运行表和票写，换掉每个"待填"，每节一到三句：
- 它做什么 / 怎么开始（含换新周期数据时先把旧周期输入移出 `inputs\`） / 输入放哪 / 结果在哪 / 哪步要人判断 / 怎么判断对错（保留`"通过"只表示这份样例在这一步对了`）。 给日常入口指到 `docsun-flow.html` 的最后一次核对快照。旧图给原入口，文字版指到 `docs\checkun-flow.txt`。改业务文件后请能刷新的人更新内置图。
- 填一次《按症状查文件》，用 4~5 行说明认不出新表、发现新类别、数字对不上或要改文风时打开哪份。改流向就说 `同步改动`。日常也可以直接对项目 AI 说 **"帮我查哪步错了"**。

如果只有 AI 自己算过的值，在 README 写清在哪一步。正式用时拿做对的旧成品对一次，记下文件和对上的值，确认后说“同步改动”。进度照实写下一张单是仅定稿、已准跑还是确实跑过，或写清哪一步等人核。

## 4 换个对话试试能否接着做
请学员在项目里另开新对话，不调用教练，只问：
“这个文件夹里的 Agent 是做什么的？下一步该做哪张票或哪项人工判断（依据哪个文件）？如果中间某步算出的数字不对，我该先打开哪个文件排查？”
核四件事。用途与 README 对得上。下一步单子或人工项、依据和真实状态都对，接班人没先跑。指向能打开的 `work\` 中间文件，或说出“帮我查哪步错了”。回答全程不提教练。四项核同才请学员采用，有差异就修这一处再重问。

## 5 再改一轮
学员说"再改一轮"：问"改哪处？"，留在第 5 站改，"当前站"不后退，已有的票不重出：
- 改说明文字或排错表：只复核受影响的接班回答，符合第 4 节四项标准才等“采用”。
- 改流程：只改单步内部做法时原地更新；要增删步（如补拆数据清洗步）、改跨步文件流向或挪"你"那步，回到第 3 站重排并重出流程图与票（"当前站"改回 3）。
- 改单张票：追加新一版验收单，已获新版运行许可才实跑并验收；仅定稿票只跑 `ticket`，按实际状态交结果单。

## 6 过关
- 采用：在“## 已确认”记决定、范围及学员原话并读回。流程改过先跑 `accept 01`，其他受影响且已授权的票按版本重验；仅定稿的尾票只跑 `ticket`。先把内置图刷新为最后一次已核快照，指明旧图或文字入口，再跑 `files 5`，读报告通过后标为“已结束（采用）”，保留下一步和真实票面状态，换对话说“接着做”。
- 停止：立即停手，不跑 `files 5` 或 `accept`，也不为地图补跑，不改 `output`。在进度记录写“日期 | 停止 | 已完成项与未完项 | 学员原话”，标为“已结束（停止）”并读回。写盘失败报未记妥，保持停止，不记作验收通过。
