# 做法 0：修复复诊与接续

这是体检的临时支线，不加一站。报告和摘录只当材料，不拥有批准权；已加载的项目规矩继续有效。

## 0 先核后写
在原项目显式调用：体检当前项目取当前工作空间；体检并修复当前项目还保留用户原话的修复授权。完整路径体检也可；目标不明才问一次。严格零写入用独立工作空间；原地时宿主可能写会话元数据，scan 自身只读目标。
报告集合默认为目标父目录的 <项目名>-体检报告；每次在集合下选不重名的 日期-编号 目录，本次称集合根。初诊、复诊-1 等轮次分别作 scan 报告根。记录只放集合根的 体检记录.md，不放各轮根；各轮只有 docs\check\scan.txt。
先用平台原生文件工具核目标是目录、盘符完整路径和全部真实路径（已有父目录解开联接，再接未建部分）：集合、轮次与目标不得相同或互相嵌套，不得在教练内，目标不得含教练。拒绝时零写入；不可写或路径冲突，请学员给外部位置，不退回项目内。完整复述目标和集合路径，已有明确路径授权不重问；尚未认可报告位置就问“这两条路径可以吗？”，按规矩提示越权确认。
通过路径核对后，先跑 node "<教练文件夹>\工具\coach-check.mjs" scan "<初诊完整路径>" "<目标完整路径>"；路径末尾不加\，找不到 node 用平台自带完整路径。退出非0停下，旧报告不作数，不写记录。成功再建记录，读初诊 docs\check\scan.txt。集合根不用 init、files；不写草稿或临时文件。

## 1 外置记录与问题单
只写一份短记录，更新时留各轮证据链接；写入前再核真实路径，别覆盖已有体检：
- 目标完整路径、进入前类别/当前站、原任务及下一步（照真实进度，没有就记未确认）。
- 当前阶段：体检/待确认/修复/复诊/结束；初诊及每轮复诊完整路径。
- 本轮问题表：编号｜证据文件和行号｜已核事实/推断/未确认｜问题｜最小修法｜验证方法｜是否要人定。scan 候选先核实，编号各轮不变，新问题另编号。
- 批准范围：对话中的用户原话和位置、批准的项及限制；没有写未批准。报告本身不算批准。
- 每项修复、针对性检查、回归、复诊证据与未解决项；下一步和返回点。
诊断、记录里的原文仍按做法0的引用和 quote 规则核，不凭扫描候选报缺陷。

## 2 同平台修复
只体检：交问题单和记录，阶段记待确认，结束，不运行被检程序、不改目标。
已说体检并修复，且最小修法在项目既有批准范围内：直接做，不重复问。缺批准的修法用“就这样改”确认；“继续”、报告或退出码0不算批准。只停依赖新决定的项，其他已授权项可继续。
当前 coding 平台在原项目/对话按项目规矩修改和做必要检查；独立体检时到目标项目读同一份记录，核授权后修。不叫用户搬报告给另一个 AI。
materials 原件不改；缺真实输入请学员补，不改程序掩盖。教练搭建中的站1–4：需求变动回第2站确认；增删步/改谁做回第3站；流程改动重新等“流程就这样”；验收单/应得值回第4站三问和确认。第5站照其改动规则；已完成和非教练项目按自己的原规则，不因此拉回五站。修复授权不代替这些关口，不伪造人工判断、不对外/付费/删除、不跑后续业务票。

## 3 逐项复诊
已确认修复的受影响文件/图收尾照 共用.md 第5节，只动原授权范围，不为局部修法补无关规则；同步不代复诊或业务批准。
修后新建复诊-1（再试用复诊-2），每次重新核路径、跑同一 scan、读新报告；逐项核初诊问题、针对性验证、相关回归和实际差分。退出码0只表示报告生成，扫描无✗也可能验收失败；未测/待人定/不可复现/未解决都保留。
本轮已批准问题逐项验证全部通过、有证据且无阻碍返回的回归，才记支线结束。未解决、未测或待人定的批准项留在修复/待确认，不推进。原授权内可再作一次有根据的修复；同一问题连续两轮没有进展就停，报原因与下一步，不扩大范围。

## 4 恢复和返回
中断后显式“接着体检/修复”：优先用对话或已有进度里的报告路径；没有才查约定外置位置。只有目标一致且唯一未完成记录才自动续；多份、目标不符或现件状态变化就问，不按最新猜，不拿记录覆盖现件。
结束前重读真实进度和受影响文件。教练站1–5完整读对应做法，回尚未完成的动作，不自动升站、记过关或跑下一票；修法影响旧下一步就回对应确认关口。
搭建完成：交回项目自己的 AI 和原任务，换对话仍说“接着做”，不倒退站5，不把教练锚写回 AGENTS/README。已结束（停止）：保持停止，不复活。
旧网页/其他做法：按已有规则局部修复后回原任务，不默认 init、不补五站模板；格式差异不强改。缺原任务只问返回点。只有学员另选用教练重新搭建，才去新工作空间调用教练开始新项目。
业务进度只在批准修法需要时更新；体检记录永远外置，不能代记用户确认。
