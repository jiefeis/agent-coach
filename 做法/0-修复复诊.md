# 做法 0：修复复诊与接续

体检、修复与复诊共用同一份外置 `体检记录.md`，全程不污染被检项目目录。

## 0 外置目录规范与先核后写（严守 scanGuard 隔离）
1. **确认目标与授权**：取学员指定的完整路径或当前工作空间作为`<被检目标>`；目标不明先问一次。若学员开场即要求“体检并修复”，原样记下其授权原话与范围。首次跨目录访问前照 `AGENTS.md` 第 3 节提示越权确认；学员拒绝则零写入停下。
2. **外置报告目录树（严禁把记录塞进 scan 轮次子目录）**：
   先用原生文件工具解开真实路径（含父目录联接），确认集合根及各轮报告根均在被检目标之外，与被检目标互不嵌套。每轮报告根是集合根下单独的直接子目录，各轮互不嵌套。目标和报告均在教练文件夹之外，目标也不能包含教练文件夹（路径冲突或不可写时请学员指定外部目录，绝不退回项目内）：
   ```text
   <目标父目录>\<项目名>-体检报告\<日期-编号>\        ← 集合根（每次新体检选不重名目录）
   ├── 体检记录.md                                    ← 唯一跨轮次追踪记录（只放集合根！）
   ├── 初诊\docs\check\scan.txt                       ← 初诊报告根（传给 scan 的目录内禁放其它文件）
   └── 复诊-1\docs\check\scan.txt                     ← 第 1 轮修后复诊报告根（每轮新建，不覆盖旧轮）
   ```
3. **执行初诊扫描**：报出目标与集合根完整路径（仅对尚未许可的位置请学员确认），核对无误后运行：
   `node "<教练文件夹>\工具\coach-check.mjs" scan "<集合根>\初诊" "<被检目标完整路径>"`
   路径末尾不加 `\`，找不到 `node` 用平台自带完整路径。退出码非 0 立即停下，旧报告不作数、不建记录；退出码为 0 后读取 `初诊\docs\check\scan.txt` 并在`<集合根>`建立 `体检记录.md`（集合根不跑 `init` 或 `files`，不留临时草稿）。

## 1 外置 `体检记录.md` 与 `P01` 问题单规范
只维护一份精炼的 `体检记录.md`，每次更新保留各轮证据路径，写入前再核真实路径防误覆写：
- **项目基线**：被检目标完整路径、项目类别/进入前当前站、原任务与原下一步（照实记录，无则标`未确认`）。
- **当前支线阶段**：`体检 / 待确认 / 修复 / 复诊 / 结束`，以及`初诊`、`复诊-1`等各轮报告根完整路径。
- **分级问题追踪表**：`编号(P01..) | 严重度(🔴硬伤/🟡建议/⚪免修) | 证据文件与行号 | 定性(已核事实/推断/待确认) | 问题描述 | 最小修法 | 验证方法 | 是否要人拍板`。`scan` 候选须经原件核实后入表；跨轮复诊保持原编号不变，新发现问题顺延新编号。
- **批准台账**：记录对话中学员的批准原话、批准项（如 `P01、P02` 或 `全部硬伤`）与限制条件。“修复全部硬伤”只覆盖已向学员展示的本轮红色编号，复诊新增问题另列。未获明确口令写`未批准`（报告本身、`继续`、`scan` 退出码 0 均不算批准）。
- **修复与复诊留痕**：逐项记录实际改动文件、针对性校验结果、复诊新报告路径、残余未决项及最终返回点。记录中的原文摘录同样遵守 `做法\0-体检.md` 第 3 节的引号与行号规范。

## 2 按授权最小修复（直连数据治理与三级回退路由）
- **纯体检模式**：交出问题单与外置记录后，阶段记`待确认`即停下，零修改目标文件。
- **授权触发条件**：
  - 学员已明确说 **`修复 P01` / `修复 P01、P02` / `修复全部硬伤` / `就这样改`**，或已说“体检并修复”且最小修法完全落在项目既有已确认规矩内 → 直接对获批项动手，不重复盘问；
  - 涉及新业务口径决定、改验收真值、增删步骤或调整人工停点的项 → 只停下询问该项决定，其余已获批且独立的修复项可先行完成。
- **同平台就地执行**：在当前平台直接按被检项目自身规矩实施修改与验证，不让学员手动搬运报告去喂给另一个 AI。
- **分类修复准则（严守边界，治本不掩盖）**：
  1. **原件与脏数据问题**：`materials\` 原件绝对只读不改；缺真实输入请学员补齐，严禁改代码掩盖缺件。若原件含脏数据且强写兼容代码有副作用，教练项目按 L1 写 `docs\rules\数据清理对照单.md`，在文件地图登记并从项目入口指明何时读取；外部项目沿用其原有说明位置。请学员将清理后的副本另存为新文件名，保留已登记基线的原件，再确认本次使用哪份；若属每周固定导出的结构性脏表且学员批准改流程，按 L2 补拆独立`清洗数据`步。
  2. **教练项目（站 1~5）联动三级回退路由**：
     - 仅单步脚本 Bug 或持续运行缺枚举白名单 → 按 L1 原地修脚本并重跑绑定基线回归；
     - 增删步骤、改`谁做`或改跨步读写路径 → 按 `做法\共用.md` 第 5 节 L2 退回第 3 站更新 `docs\run-flow.md`（重新等`流程就这样`）、重画 `Archify` 图并对齐票据；
     - 需求边界变动回第 2 站确认；验收真值变动回第 4 站补齐独立真值来源请学员确认；第 5 站照做法 5 规则更新排错表。
  3. **已交付或非教练外部项目**：严格顺着其原有架构与目录习惯做最小局部修复，**绝不强行跑 `init`、绝不塞入五站模板或教练路径**。修复授权不能代替业务人工拍板，不对外发送/付费/删业务文件，也不擅自往后跑未授权业务票。

## 3 强制新建复诊轮次与两轮熔断机制
1. 已获批修复项涉及的关联文件/流程图收尾，按 `做法\共用.md` 第 5 节在原授权范围内对齐（不为局部小修强补无关大规矩；文件同步不代替复诊与业务验收）。
2. **修后必建新目录跑复诊**：新建 `<集合根>\复诊-1`（后续轮次顺延 `复诊-2`），核对路径后重跑同一 `scan` 命令读取新报告，并对每项已修问题执行**针对性实测验证**（如教练项目的 `inputs` / `flow` / `ticket N` / 基线 `accept N`，或外部项目的语法与样例干跑校验），逐项比对初诊问题与真实文件 diff。
3. **判定与两轮无进展熔断**：
   - 只有本轮全部已批准项的针对性验证通过、复诊无新增回归硬伤且证据齐全时，才将体检支线标为`结束`。
   - 未测、待人拍板或未解决项如实保留在`待确认 / 修复`状态，绝不蒙混过关。
   - 若某项修复后复诊仍未解决，在原授权范围内最多再做 **1 次**有明确依据的修正；**同一问题连续两轮复诊无实质进展立即熔断停下**，如实汇报根因与备选方案交学员拍板，严禁盲目死循环扩大修改面。

## 4 恢复进度与无损归位
- **跨会话续修**：学员说“接着体检/修复”时，优先读当前对话或进度指明的报告路径，无则查找约定外置目录 `<目标父目录>\<项目名>-体检报告\`；仅当目标一致且存在唯一未完记录时续接，多份记录或归属不明时列出路径请学员指定，不靠猜。复诊未跑完第 3 节前不得跳回日常业务。
- **支线结束精准归位**：重读被检项目真实进度与已改文件，按进入前身份无损接回：
  - **教练搭建中（站 1~5）**：第 5 站尚未采用或停止的，回原有接班演练或决定，不代为采用。完整读对应站做法，回到尚未完成的动作或因本次修复触发的确认关口，不自动升站、不代记过关、不偷跑下一张票。
  - **已结束（采用）或旧版搭建完成**：正式交回项目自身 AI 与原业务任务（后续日常对话直接说`接着做`），不倒退回第 5 站，确保 `AGENTS.md` / `README.md` 零教练字样残留。
  - **已结束（停止）**：保持停止状态，不借修复复活业务执行。
  - **外部非教练项目 / 旧网页项目**：局部修复验证通过后直接交回原工作流；仅当学员主动要求用教练重新规范化搭建时，才引导去新空目录调用教练开始新项目。
- 业务项目的 `docs\PROJECT_INDEX.md` 仅在获批修法本身按做法要求更新时才动；`体检记录.md` 永远留在项目外，绝不用体检记录顶替学员的业务确认记录。
