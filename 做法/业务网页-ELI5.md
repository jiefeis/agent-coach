# 业务网页 · ELI5

选了网页交付的那张票才用这一页。项目的 `docs\run-flow.html` 用来查哪一步读写什么。日报、周报或复盘网页由业务票交付，里面是这批数据和异常去向。

## 发给项目 AI

> 先读已确认任务单、运行表和本票。给我看网页给谁看、读哪份当批数据、缺数据如何停、异常退哪一步。等我确认这版验收单可以跑，才把教练包内的 `工具\eli5-report.mjs` 按原字节复制到项目 `scripts\eli5-report.mjs`。同字节就复用，同名已有不同脚本先请我决定。给我当批 JSON、实际网页和一次好坏样本的验收结果。缺当批数据先停。改定时任务、写线上和补历史另问我。

把真实样例中的日期、结论、读入值、判断依据和去向填进 JSON。拿不到的字段写 `null`，页面会标待核。实际是零才写 `0`。下面是可跑的演示数据，别拿来顶业务数据。

```json
{
  "batch": {"报告日": "2026-11-25"},
  "date": "2026-11-25",
  "title": "选题日报",
  "audience": "内容负责人",
  "conclusion": "一条可用，一条拦回，一条等补证。",
  "stats": [{"label": "已核条目", "value": 2, "unit": "条"}],
  "items": [
    {"label":"春季选题","state":"正常","input":"本批一条记录","rule":"来源日期等于报告日","basis":"当批清单第 2 行","action":"交编辑核选","exception":"退回采集"},
    {"label":"旧批条目","state":"异常","input":"上期记录","rule":"来源日期等于报告日","basis":"当批清单第 3 行","action":"暂缓采用","exception":"退回补当批记录"},
    {"label":"待补出处","state":"待核","input":"新条目","rule":"须有可核出处","basis":null,"action":null,"exception":"请采集人补出处"}
  ],

```

项目 AI 用已定的真实路径运行。命令可以在其他目录启动。

```text
node "<项目>\scripts\eli5-report.mjs" "<项目>\work\03-日报数据.json" "<项目>\work\03-日报初稿.html"
node "<项目>\scripts\eli5-report.mjs" --check "<项目>\work\03-日报初稿.html"
```

## 验收与接班

- 读回网页 head 的 `eli5-report/1` 和本批 `coach-batch`，校验命令要同时退出 0 和显示“通过：ELI5 业务网页”。手写旧页的“跳过”沿原约定处理。
- 双击业务成品。选正常、异常、待核，核图上箭头、可见条数和实际条目。打开证据查出处，待拍板事项可复制给 AI 核对。填写决定不算批准。
- 好样本对当批数和真实产物，坏样本对拦截原因。过站时让项目 AI 只用项目里的脚本和当批 JSON 复做一遍。每批改数据即可，脚本内已经有版式。
