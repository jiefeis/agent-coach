# 做法 0：体检

## 0 路径隔离与只读铁律
1. 先读 `做法\0-修复复诊.md` 第 0 节，核实**被检目标完整路径**、**外置报告集合路径**及用户授权范围。
2. **严格只读目标**：体检阶段绝不运行被检项目内的业务脚本、绝不安装依赖、绝不修改或新增被检项目里的任何业务文件（原地会话仅允许宿主平台自身的会话元数据例外）。
3. **隐私边界**：不读取 `.workbuddy\memory` 内容；若某项信息仅可能存于平台记忆中，直接列入待确认问题向学员核实。 `scan` 只记文件名、大小、修改时间，`quote` 连记忆目录都不索引。只从普通项目文件看线索。

## 1 记录返回点与识别项目身份
先读取被检项目的实际现状，记下进入体检前的**项目身份与返回点**（体检期间原站号与原状态保持不变）：
- **教练搭建项目**：以 `docs\PROJECT_INDEX.md` 的`当前站`与真实文件核对为准（区分：站 1~4 搭建中、第 5 站待交接、`已结束（采用）` / 旧版`搭建完成`、`已结束（停止）`）。
- **外部非教练项目 / 旧网页项目**：按其原有入口文件（如 `AGENTS.md`、`CLAUDE.md`、`SKILL.md`、`README.md` 或主脚本）识别原做法与当前进度；**格式与五站不同不算故障**，报告中的“第 1 站清单”仅作结构对照参考，除非学员主动要求用教练重搭，否则绝不要求补齐五站模板文件。

## 2 跑 scan 与五维取证核实
1. 按 `做法\0-修复复诊.md` 第 0 节选定干净的初诊目录，运行：
   `node "<教练文件夹>\工具\coach-check.mjs" scan "<初诊完整路径>" "<被检目标完整路径>"`
   退出码非 0 立即停下说明原因，旧报告不作数；退出码为 0 则完整读取 `<初诊完整路径>\docs\check\scan.txt`。 判断是否通过要看报告首行。检查没过就照读 stdout 最后三行，严禁报修好/已通过。
2. **scan 仅作线索，取证必须读原件**：
   - 先围绕下方五维列出不超过 8 份核心未读文件，一次性完整读取（不分批截断）；若流程图、图源与运行表同在则成对读取核对。
   - 遇到同一任务的多个票据或计划文件，先列全集合，逐件核清实际用途、上下游引用关系，区分`当前生效 / 历史归档 / 待核孤岛`，不单凭状态字样妄下结论。
3. **按五维全面核查（打通 v1.20 数据治理与持续运行标准）**：
   - **维度 ① 完成度与契约一致性**：当前做到哪一步、还差哪些未跑票或待确认项；跨文件硬冲突（缺必填字段、上下游路径断链、步号/票号错位）必须记下两处精确文件与行号；未证实的路径或纯措辞差异列为“待核”，不谎报一致也不擅自判错。*(注：`docs\check\` 首行复制带来的历史路径、旧票已勾判定的历史站号记录均属正常痕迹，不算冲突。)*
   - **维度 ② 原件保护**。核脚本有没有绕进只读原件，以及表头、单位、小计行有无混在一起。碰到偶尔出错的表，建议另存一份修好。每次导出都这样，建议先用程序单独洗一遍。
   - **维度 ③ 长期记忆与未接线文件**：排除历史归档、模板、素材、图源后，核查是否存在“无任何入口（进度/README/AGENTS/上游步）引用”的悬空规则或脚本；明确区分“现件未接线”与“缺件断链”，体检只如实报告，绝不删文件。
   - **维度 ④ 图和文件能否对上**。内置活地图核主表和这批实物，过期就请 AI 刷新。旧 Archify 保留原图，核图、图源和主表。已选文字版看文字流程。外来图按 `做法\共用.md` 第 2 节核。打不开或坏了如实报告。 一条边接不上，仍核其它箭头、步名、产物和人工关口。
   - **维度 ⑤ 架构适配与持续运行防漂移**：对照 `做法\架构推荐表.md` 核验当前实际架构与业务特征是否匹配（教练项目站 1~3 为“尚未搭完”，站 4 起为固定流程，核对⑥记录是否自洽）；对周期复跑项目，检查是否具备**固定基线 + 当期守恒等式 + 已知枚举白名单拦截**，以及是否残留未转正的“AI 同源试算”风险。

## 3 后台留证，屏幕只给一张诊断卡
将五维结论、双端 `文件:行号`、哈希及跨轮固定编号 `P01` 等记入外置 `体检记录.md`，区分已核事实、推断、待确认。初诊读 `初诊\docs\check\scan.txt`，修后取新轮 `复诊-1\docs\check\scan.txt`。核查“卡站与升级线索”：多出文件先查用途与引用，基线差异先核本次要用的现件，残留锁先确认没有交付在跑。旧票兼容归白色，旧计算票建议补真值归黄色，新票缺授权、指纹或真值经核实归红色。连续两轮复诊无实质进展立即熔断。 初诊的 `snapshot.json` 冻结改前指纹；各轮的新快照自动比初诊，同一轮不用新记录盖旧结果。有运行表就给学员 `scan-map.html` 的本轮实际入口。点一步能看到进门、规则、出门或退回，还能复制这一处给项目 AI 的指令。
外置记录短引原件用「原话」（文件:第N行），每处最多 30 字；连续 10 字相同须引用，单提路径用「」。草稿用标准输入交 `quote`，核到引号外原文 0 处。学员屏幕严禁出现 P01、五维、文件:行号、哈希或检查器命令。用自己的话，按四块发：

1. `📍 当前进度：项目体检（原停点）｜正在做：核对卡点｜Agent 搭建教练 v2.1.0 (2026-11-25)`。已交付、已停止或外部项目照原进度写，避免硬套站号。
2. `【先说结论】` 说清哪部分仍可用、哪里卡住。例如查明只是旧记录时说“项目没坏，已经通过的三步和做出的结果都会保留”。有实质故障或尚未核实就照实说。
3. `【发现了什么 & 修完会怎样】` 用 `🔴 挡路问题`（最多 3 项）、`🟡 稳健建议`、`⚪ 旧版写法自动兼容`。用屏幕序号“第 1 项”等对应后台编号；每条红黄项讲清问题是什么、推荐怎么修、不会动哪些已有成果、修完后会怎样。白项说明可直接沿用。需确认的输入或口径写进对应项。
4. `👉 你现在只需要回：「打开诊断图，点第一处卡点」`。若学员只想处理骨架，给 `只修第 1 项`、`修复全部硬伤` 或 `按建议修好并接着做` 中适用的一条。定制修理、写线上、补历史或改定时任务，先把对应指令交项目 AI，等学员另行确认。

## 4 严守红线（不说的话）
- `scan.txt` 首行的`通过`只代表静态扫描未命中失败项 `✗`，绝不对学员说“项目完全没问题/体检过了”，也不打百分比分数。
- 缺图先读本轮选择。内置图缺了请 AI 按表生成，过期请 AI 刷新。旧图请按原做法补图或找回源文件。已选文字版直接看文字流程。外部项目照它原来的入口，只报核到的事实。 学员想升级原图时，先确认“只升级项目内活地图，先备份原图”，照做法 0 修复复诊执行。
- 诊断阶段零修改目标；进入修复后严格按学员点名批准的范围动刀，绝不伪造或代补学员确认记录。
