# 做法 0：体检

## 0 路径隔离与只读铁律
1. 先读 `做法\0-修复复诊.md` 第 0 节，核实**被检目标完整路径**、**外置报告集合路径**及用户授权范围。
2. **严格只读目标**：体检阶段绝不运行被检项目内的业务脚本、绝不安装依赖、绝不修改或新增被检项目里的任何业务文件（原地会话仅允许宿主平台自身的会话元数据例外）。
3. **隐私边界**：不读取 `.workbuddy\memory` 内容；若某项信息仅可能存于平台记忆中，直接列入待确认问题向学员核实。

## 1 记录返回点与识别项目身份
先读取被检项目的实际现状，记下进入体检前的**项目身份与返回点**（体检期间原站号与原状态保持不变）：
- **教练搭建项目**：以 `docs\PROJECT_INDEX.md` 的`当前站`与真实文件核对为准（区分：站 1~4 搭建中、第 5 站待交接、`已结束（采用）` / 旧版`搭建完成`、`已结束（停止）`）。
- **外部非教练项目 / 旧网页项目**：按其原有入口文件（如 `AGENTS.md`、`CLAUDE.md`、`SKILL.md`、`README.md` 或主脚本）识别原做法与当前进度；**格式与五站不同不算故障**，报告中的“第 1 站清单”仅作结构对照参考，除非学员主动要求用教练重搭，否则绝不要求补齐五站模板文件。

## 2 跑 scan 与五维取证核实
1. 按 `做法\0-修复复诊.md` 第 0 节选定干净的初诊目录，运行：
   `node "<教练文件夹>\工具\coach-check.mjs" scan "<初诊完整路径>" "<被检目标完整路径>"`
   退出码非 0 立即停下说明原因，旧报告不作数；退出码为 0 则完整读取 `<初诊完整路径>\docs\check\scan.txt`。
2. **scan 仅作线索，取证必须读原件**：
   - 先围绕下方五维列出不超过 8 份核心未读文件，一次性完整读取（不分批截断）；若流程图、图源与运行表同在则成对读取核对。
   - 遇到同一任务的多个票据或计划文件，先列全集合，逐件核清实际用途、上下游引用关系，区分`当前生效 / 历史归档 / 待核孤岛`，不单凭状态字样妄下结论。
3. **按五维全面核查（打通 v1.20 数据治理与持续运行标准）**：
   - **维度 ① 完成度与契约一致性**：当前做到哪一步、还差哪些未跑票或待确认项；跨文件硬冲突（缺必填字段、上下游路径断链、步号/票号错位）必须记下两处精确文件与行号；未证实的路径或纯措辞差异列为“待核”，不谎报一致也不擅自判错。*(注：`docs\check\` 首行复制带来的历史路径、旧票已勾判定的历史站号记录均属正常痕迹，不算冲突。)*
   - **维度 ② 原件保护与数据治理健康度**：检查是否有脚本直接修改或写穿只读原件（如 `materials\` 软链接/目录写穿）；检查输入原件是否存在未治理的结构性脏数据（非首行表头、合并单元格、混杂单位或小计行）却在业务脚本中黑盒硬猜（应建议走 L1 源头清理对照单或 L2 拆独立数据清洗步）。
   - **维度 ③ 长期记忆与未接线文件**：排除历史归档、模板、素材、图源后，核查是否存在“无任何入口（进度/README/AGENTS/上游步）引用”的悬空规则或脚本；明确区分“现件未接线”与“缺件断链”，体检只如实报告，绝不删文件。
   - **维度 ④ 流程图一致性**：先归类现状（有可查看图 / 仅有图源 / 仅有文字流程）；有图或外来图源时，严格按 `做法\共用.md` 第 2 节四项标准与运行表逐行比对，指明差异行号并给出一句改法；打不开的图如实标“未确认”。
   - **维度 ⑤ 架构适配与持续运行防漂移**：对照 `做法\架构推荐表.md` 核验当前实际架构与业务特征是否匹配（教练项目站 1~3 为“尚未搭完”，站 4 起为固定流程，核对⑥记录是否自洽）；对周期复跑项目，检查是否具备**固定基线 + 当期守恒等式 + 已知枚举白名单拦截**，以及是否残留未转正的“AI 同源试算”风险。

## 3 输出《体检分级诊断单》与一屏拍板（告别逐题盲问）
### 引用与防照抄纪律
- **精准短引，严禁大段抄原文**：凡在诊断结论或外置记录中引用被检文件原文（连续 10 个及以上相同字符，含中英文词与代码标识符），必须用引号包裹并附精确出处与行号（格式：`"摘录内容"（文件:第N行）`，单处引号内连标点空格不超过 30 字，超长用 `...` 截断）；引号外提及文件名、目录名或路径时单独用「」包裹（如「docs\run-flow.md」）。其余分析一律用你自己的大白话复述（仅换人称或斜杠仍算照抄）。
- **安全调用 `quote` 核验**：需要用 `quote` 校验草稿是否存在“引号外原文”时，通过标准输入管道将草稿喂给 `node "<教练文件夹>\工具\coach-check.mjs" quote "<被检目标完整路径>"`（避免在 PowerShell 命令行参数内直接拼接多行带引号长文本引发转义报错；草稿不落盘进被检项目），确认首行显示 `引号外原文：0 处` 后发出。

### 屏幕诊断报告结构
按以下顺序清晰呈现，事实、推断与待核严格分开：
1. **一句话总评与架构定性**：报明项目类型、当前所处阶段（或原规矩进度）、实际采用的架构及对照 `做法\架构推荐表.md` 的第一版建议（说明先做哪一类、守哪些已定规则、何处停下问人，不用“照五站搭”笼统省略）。
2. **五维体检摘要**：按【完成度 → 数据治理与持续运行 → 长期记忆接线 → 流程图 → 架构】五点简明汇报已核事实。
3. **分级问题清单（编号 `P01`、`P02`…，跨轮次固定）**：
   - **🔴 硬伤必修**：阻断运行、篡改原件、上下游路径断链、口径无依据自证、越权跳过人工停点等真故障（附双端 `文件:行号` 证据与最小修法）。
   - **🟡 治理与防漂移建议**：脏数据未分流、周期任务缺已知枚举白名单拦截、同源试算未转正、流程图未同步等隐患（给清最小改进动作）。
   - **⚪ 格式差异免修**：非教练项目或旧版项目的命名/排版差异，明确告知“不影响使用，无需改动”。
4. **一屏确认与修复菜单（替代多轮单题追问）**：
   - 若 `scan.txt` 的 `## 请学员确认` 或取证中存在影响定性的未明事实（最多 3 项），整理成**带推测默认项的一屏确认清单**请学员一次勾选或补充；
   - 明确给出下一步可选口令：
     - 说 **`修复 P01、P02`**（或 **`修复全部硬伤`**）：按 `做法\0-修复复诊.md` 对点名项执行最小修复并自动跑复诊；
     - 说 **`只看报告`**：保留外置 `体检记录.md` 结束体检，被检项目零改动；
     - 若学员想用教练从头重搭：提示到新空文件夹调用教练说 `带我开始新项目，体检报告 <外置记录路径>`（绝不默认另建）。

## 4 严守红线（不说的话）
- `scan.txt` 首行的`通过`只代表静态扫描未命中失败项 `✗`，绝不对学员说“项目完全没问题/体检过了”，也不打百分比分数。
- 仅有图源或文字流程时：教练项目说明“可回第 3 站用已安装画图能力按已确认图源补生成并校验，缺画图能力如实说明且不挡后续运行”；非教练项目仅在学员选重搭时提第 3 站画图，否则只报现状。
- 诊断阶段零修改目标；进入修复后严格按学员点名批准的范围动刀，绝不伪造或代补学员确认记录。
