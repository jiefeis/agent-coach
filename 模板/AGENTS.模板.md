## 开工
按顺序读：docs/PROJECT_INDEX.md → docs/run-flow.md → 当前票（在 docs\tickets\）。docs\ 里运行表和票写的"你"都指使用者。
进度记录的"当前站"还写着 1 到 5 时，项目还在搭建：使用者调用了搭建技能就照它做；没调用时，1 到 4 请使用者先调用它，5 只回答使用者的问题、不跑票（要跑票，请他先把第 5 站做完）。"当前站"写着"已结束"：念出"当前站"那一行，停下。
搭建完成后，使用者说"接着做"：报出下一张是票几、它的验收单确认了没有，然后停下。验收单已确认的，等使用者说"就这样跑"。流程已全部完成的，说出这一点。

## 口令
每个口令只有一个意思。
| 使用者说 | 意思 |
|---|---|
| 票 N 验收单确认 | 只定稿这张票的验收单，不跑 |
| 就这样跑 | 确认眼前这一版（验收单或改动）并开跑，只在 AI 出了单子以后有效 |
| 票 N 通过／票 N 不通过：第 X 项看到的是…… | 使用者对这张票下的判断 |
| 开下一张 | 出下一张票和验收单，停下等使用者 |
| 就这样改 | 同意 AI 给的修法 |
| 继续 | 做下一步，遇到要批准的地方照样停；"继续"不算任何批准 |
| 以后都要这样 | 改本项目的 AGENTS.md，改一条记一行日期 |
| 样例换了 | "放哪"的子文件夹里有一份换成了改好的，从第 1 步重跑 |

## 跑票
- 票"怎么做"写"写程序"的，程序用 Node 自带模块写，不装包，只读 CSV/TXT，文件名 scripts\NN_短名.js，结果不写进 materials、inputs\；写"AI 亲自做"的，你自己读"从哪拿"、把结果写进"放到哪"，不写程序，结果第一行写"AI 亲自做"。
- 输入文件名带 <参数> 的（如报告周），开跑前问使用者这次的值，写成命令的第 1 个参数。
- 验收单写了坏输入的，放进 work\NN-坏输入\，再跑一次，命令末尾加这个文件夹的完整路径；程序收到这个文件夹，就从它读，结果也写进它。
- 第 2 轮起，开跑前先把这张票上一轮的产出挪进 work\<票号>-第<上一轮>轮\正常\（保留 work\、output\ 那一层），坏输入文件夹里程序写的结果挪进同一轮的 坏输入\，再跑。
- 票里没写清、你自己定了取法的，在结果单"做了什么"里写明。
- 按票里"AI 自检"逐条核。没有检查脚本时，逐条手核，结果单写"未用脚本核"。
- 结果追加在"## 结果"这一节的最后，开头写"第 N 轮｜按第 K 次确认（第 V 版）的验收单"。前面的轮次保持原样。
- 交结果单后停下，等使用者判。使用者说"票 N 通过"后，把 docs/PROJECT_INDEX.md 的"下一句该说"改成下一张票和文件名；没有下一张就写"这条流程已全部完成"。
- 不通过先诊断：先保持原样，找第一处对不上的地方，说清错在哪、证据在哪、怎么修。使用者说"就这样改"才改。

## 开下一张
- 前一张判 ✓ 才开。照 docs\tickets\01-认出输入.md 的格式出票，去掉"走完一步 vibecoding 的判定"那一节；验收单四项和 AI 自检等问完再填。
- 验收单用三个问题问使用者，一次问一个：
  1. 拿哪份样例测？
  2. 这份样例在这一步应该得到什么？请说 1 到 3 个你确定的值。
  3. 什么样的结果你一看就知道错了？
- 应得结果只收使用者打字给的值。
- AI 自检照票 01 的写法：每条以"- "开头，前面不加"[ ]"；值照那份文件里的写法（文件里没有千分位就不加）；验收单写了坏输入的，另写一行查坏输入文件夹里程序写的结果。
- 使用者每确认一次，在"## 确认记录"加一行"- 第 K 次确认（第 V 版）：<日期>｜原话"，原话要有"就这样跑"或"票 N 验收单确认"。改验收单时在"## 确认记录"前追加"## 验收单（第 V+1 版）"，旧版留着。
